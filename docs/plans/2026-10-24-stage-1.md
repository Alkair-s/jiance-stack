# jiance-stack stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An installable, self-contained Claude Code plugin that covers the owner's next use: working on an existing
project (onboard, change request, testing, helper gate, reviews, investigation skills), as a coherent system.

**Architecture:** A Claude Code plugin repo. Skills are Markdown (`skills/<name>/SKILL.md`, flat). A SessionStart
hook injects the router skill. Mechanical rules are Bash scripts with plain-Bash tests. Skill behaviour is checked
with `claude plugin eval` cases whose no-plugin baseline is the "fails before" run.

**Tech Stack:** Claude Code 2.1.310+ plugin format, Bash (Git Bash on Windows, POSIX elsewhere), `claude plugin
validate`, `claude plugin eval`. No other dependency (P1).

**Spec:** `docs/specs/2026-10-24-jiance-stack-design.md` (read §5, §6, §7.2, §7.3, §7.4, §7.5, §9, §11 first).

## Global Constraints

- English only. UTF-8 without BOM. Scripts, JSON and `.cmd` files are ASCII only. Markdown may use Unicode but
  **no em dash (U+2014)** anywhere in the repo (P3).
- Examples in skills and docs: language-agnostic first; concrete ones in Python, Go or PowerShell. Kotlin or Wall
  Rose only next to one of those, never alone (design §11).
- No personal details: no device names, local paths (`E:\...`, `C:\Users\...`), names other than upstream authors,
  emails, account data. Author in manifests: `Alkair-s` (GitHub handle), no email.
- Subagent models: only `opus` or `sonnet` aliases, which resolve to Opus 5.5 / Sonnet 5.5 or newer. Never `haiku`
  or pinned older IDs. Roles come from `config/models.md` (design §6.5).
- Precedence text, verbatim in the router: "1. The owner's direct instructions. 2. The project's own rules
  (CLAUDE.md, contracts, principles, decision log, written overrides). 3. jiance-stack defaults
  (principles/defaults.md). 4. Individual skill instructions."
- Every adapted skill starts, right after its frontmatter, with exactly one credit line:
  `> Adapted from <repo> \`<path>\` at \`<short-sha>\` by <author>, MIT License. See NOTICE and UPSTREAM.md.`
- Upstream pins: superpowers `https://github.com/obra/superpowers` at `2ce8aa1`; pstack and thermos
  `https://github.com/cursor/plugins` at `e73df47`. Copy only from these (design §11).
- Adaptation rules for every copied skill:
  - Cross-references point to `jiance-stack:<skill>`; `test-driven-development` and pstack `tdd` become
    `jiance-stack:testing`.
  - Cursor mechanics (Task tool, `readonly`, `pstack-models.mdc`, model slugs, `generalPurpose`) become the Claude
    Code Agent tool (`subagent_type: Explore` for read-only, `general-purpose` otherwise) with models from
    `config/models.md`.
  - Remove `disable-model-invocation: true` (the router must be able to call them).
  - Plan and review steps mention the approval points (design §6.2) and the helper gate (§6.4) where they write or
    judge code.
- Commits: Conventional Commits, scope = area (`feat(skills): ...`, `test(scripts): ...`, `docs(readme): ...`),
  each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `stage-1`; merge
  to `main` only after the owner's OK.
- Files of about 300 lines at most (P14). A skill that needs more moves detail to `references/`.

## Review Focus

1. **superpowers still enabled next to jiance-stack:** both routers inject; the hook must warn in its injected
   text and never fail the session. Test in Task 4 (`detects superpowers` case).
2. **Hook on Windows with a broken PATH or CRLF checkout:** the session must start and the router text still be
   injected. Pinned by `.gitattributes` (Task 1) and the `runs with empty PATH` test (Task 4).
3. **Existing project with partial structure** (say a README and a CHANGELOG, no contracts): `onboard-project`
   treats what exists as rules, never edits it, and offers only the missing pieces, with approval. Eval case in
   Task 13 (`partial structure`).
4. **Project rule conflicting with a default** (the project's commits are not Conventional Commits): the project
   wins and the conflict is mentioned once. Eval case in Task 13 (`project rule wins`).
5. **Trivial private code triggering the helper gate:** a local lambda inside one function must not start a
   review. Eval case in Task 6 (`private one-off is not gated`).
